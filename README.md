# Front End Dinametra 

**Tarea de Prueba para Ingeniero Front-End: Dashboard Interactivo** 

**Descripción General:** 

Construye un dashboard interactivo que visualice datos de una API pública de tu elección. El dashboard debe incluir gráficos, filtros y diseño responsivo. Esta tarea evaluará tu habilidad para manejar datos, crear visualizaciones dinámicas y diseñar una interfaz de usuario responsiva. 
**Requisitos:** 
1. **Visualización de Datos:** - **Fuente de Datos:** - Elige una de las siguientes APIs públicas: - API de OpenWeatherMap - API de CoinGecko - APIs Abiertas de NASA - API del Banco Mundial - API de Open AQ Platform - API de Spotify - API de IMDB - Asegúrate de poder obtener datos relevantes de la API seleccionada. - **Gráficos:** - Implementa al menos dos tipos de gráficos relevantes para la fuente de datos elegida. - Utiliza una biblioteca de gráficos como Chart.js, D3.js, o Recharts. 
2. **Filtros e Interactividad:** - **Filtros de Datos:** - Proporciona filtros apropiados basados en la fuente de datos elegida (por ejemplo, país, ciudad, criptomoneda, rango de fechas). - Asegúrate de que los gráficos se actualicen dinámicamente según los filtros seleccionados. - **Tooltips y Leyendas:** - Implementa tooltips para mostrar información detallada al pasar el ratón sobre los puntos de datos. - Incluye leyendas para ayudar a los usuarios a entender los datos representados en los gráficos. 
3. **Diseño Responsivo:** - **Disposición:** - Asegúrate de que la disposición del dashboard se adapte a diferentes tamaños de pantalla, incluyendo escritorios, tabletas y dispositivos móviles. - Utiliza CSS Grid o Flexbox para crear una disposición flexible y responsiva. - **Estilo:** - Aplica principios de diseño modernos y limpios. - Asegúrate de que el dashboard sea visualmente atractivo y fácil de usar en todos los dispositivos. 
4. **Calidad del Código:** - **Modularidad:** - Escribe código modular, reutilizable y bien documentado. - Separa los componentes lógicamente (por ejemplo, componentes separados para cada gráfico y filtro). - **Mejores Prácticas:** - Sigue las mejores prácticas en HTML, CSS y JavaScript (o TypeScript si lo prefieres). - Utiliza características modernas de JavaScript y bibliotecas/frameworks (por ejemplo, React, Vue.js o Angular). 
5. **Rendimiento:** - **Optimización:** - Optimiza el dashboard para el rendimiento, asegurando tiempos de carga rápidos e interacciones fluidas. - Maneja grandes conjuntos de datos de manera eficiente. - **Manejo de Errores:** - Implementa manejo de errores para las solicitudes de API. - Muestra mensajes de error amigables si no se pueden obtener los datos. 
6. **Accesibilidad:** - **Navegación con Teclado:** - Asegúrate de que todos los elementos interactivos sean accesibles mediante el teclado. - **Compatibilidad con Lectores de Pantalla:** - Usa atributos ARIA adecuados y asegúrate de que el dashboard sea utilizable con lectores de pantalla. 
7. **Compatibilidad entre Navegadores:** - **Pruebas en Navegadores Múltiples:** - Asegúrate de que el dashboard funcione de manera consistente en los navegadores más comunes (por ejemplo, Chrome, Firefox, Safari). 
8. **Pruebas:** - **Pruebas Unitarias:** - Escribe pruebas unitarias para tus componentes utilizando un marco de pruebas como Jest o Mocha. 
9. **Documentación:** 
- **Documentación del Código:** 
    - Proporciona una documentación clara y completa de tu código y enfoque en el archivo README.md. 

**Entregables:** 
1. **Código Fuente:** - Proporciona el código fuente completo a través de un repositorio de GitHub. - Incluye un archivo README.md con: - Instrucciones sobre cómo configurar y ejecutar la aplicación. - Una breve explicación del enfoque adoptado. - Cualquier suposición realizada y problemas conocidos. 
2. **Demostración en Vivo:** - Despliega el dashboard en un servicio de hosting (por ejemplo, GitHub Pages, Netlify, Vercel) y proporciona un enlace a la demostración en vivo. 
3. **Capturas de Pantalla:** - Incluye capturas de pantalla del dashboard en diferentes estados (por ejemplo, carga inicial, después de aplicar filtros) en el archivo README.md. **Criterios de Evaluación:** 
1. **Habilidades para Resolver Problemas:** - ¿Qué tan bien entiendes e implementas los requisitos? - ¿Eres capaz de manejar posibles problemas como errores de API o datos vacíos de manera adecuada? 
2. **Calidad del Código:** - ¿Es el código limpio, bien organizado y mantenible? - ¿Se siguen las mejores prácticas en términos de estructura del código y patrones de diseño? 
3. **Creatividad:** - ¿Propones soluciones o elementos de diseño innovadores? - ¿Vas más allá de los requisitos básicos para mejorar la experiencia del usuario? 
4. **Atención al Detalle:** - ¿Es la aplicación visualmente atractiva y fácil de usar? - ¿Hay errores o problemas de usabilidad? 
5. **Uso de Herramientas:** - Aunque el uso de herramientas como ChatGPT es aceptable, la implementación final debe demostrar tu comprensión y capacidad para programar de manera independiente. - Busca indicios de tu propio proceso de pensamiento y habilidades para resolver problemas en lugar de solo código copiado. 
6. **Accesibilidad:** - ¿Es el dashboard accesible para usuarios con discapacidades? - ¿Se pueden usar todas las funciones con un teclado y un lector de pantalla?
